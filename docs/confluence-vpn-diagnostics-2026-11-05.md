# Проверка серверного доступа к Confluence через VPN, 05.11.2026

Итог: авторизация в `internal-service.example.invalid` и туннель AnyConnect работают с сервера
`192.0.2.122`, однако Confluence через этот VPN недоступен. Серверный
коннектор пока не перенесён; действующий ноутбучный сервис не останавливался.
Пароли и Confluence PAT в этот отчёт, образ или конфигурацию не записывались.

## Что мешает прямому доступу

`confluence.example.invalid` разрешается в `192.0.2.104`. Обычный маршрут сервера
ведёт в Docker-мост `br-2feeabe87bc0` с подсетью `192.0.2.0/16`, принадлежащей
другому проекту `totum-production_database`. Это пересечение адресов.

Предыдущая ограниченная проба через `br0` и шлюз `192.0.2.254`, включая
временный маршрут ровно к одному адресу, также дала HTTPS timeout. Временный
маршрут был удалён. Следовательно, обход Docker-подсети сам по себе не обеспечил
доступ до корпоративного сервиса. Чужая сеть не изменялась.

## Результаты VPN-пробы

| Проверка | Фактический результат |
| --- | --- |
| DNS VPN на сервере | `192.0.2.131`, `192.0.2.132` |
| DNS VPN на ноутбуке | `178.238.122.17` |
| HTTPS к внешнему VPN-адресу с сервера | HTTP 200, TLS verification 0 |
| Авторизация OpenConnect / AnyConnect | Успешна, туннель `rag-vpn0` поднялся |
| Выданный VPN IPv4 в диагностической сессии | `192.0.2.171` |
| Выданные VPN split include маршруты | 24; `192.0.2.104` не входит в них |
| Проверяемый маршрут в изолированном контейнере | `192.0.2.104 dev rag-vpn0 src 192.0.2.171` |
| HTTPS Confluence через этот маршрут | curl 28, HTTP 000, TCP не установлен |
| Счётчики TUN за HTTPS-пробу | TX +7 пакетов, RX +0 пакетов |
| RAG после проверки | `/api/v1/health` HTTP 200, TLS verification 0 |
| Очистка | Временный контейнер удалён, маршрут хоста прежний |

Внешний VPN IP был указан через локальный параметр `--resolve`, с исходным
именем `internal-service.example.invalid` и обычной проверкой сертификата. Глобальный DNS
не менялся. На внутреннем адресе первая HTTPS-проверка не смогла построить
доверенную цепочку; отключение проверки TLS не использовалось.

Отсутствие адреса в split include само по себе не доказывает запрет ACL.
Но сочетание принудительно выбранного маршрута через TUN, исходящих пакетов,
отсутствия входящих пакетов и TCP timeout показывает, что рабочего пути к
Confluence за этим туннелем нет. Отличить VPN ACL, обратную маршрутизацию
и недоступность назначения по этим данным нельзя.

## Что нужно от сетевой стороны

Подтвердить, должен ли demo-VPN давать этой учётной записи доступ к
`confluence.example.invalid` (`192.0.2.104:443`). Если да, проверить профиль
AnyConnect и необходимые split маршруты, разрешение TCP/443 от VPN-пула,
дальнейший маршрут и обратный путь. Добавление маршрута на клиенте не заменяет
разрешение на VPN-шлюзе.

Если demo-VPN предназначен для другой сети, нужен профиль VPN с доступом
к Confluence либо согласованный прямой путь от сервера к корпоративной сети.
Второй вариант также требует устранить пересечение с Docker маршрутом;
пересоздавать чужой bridge без владельца проекта нельзя.

После подтверждённого HTTPS можно отдельно переносить коннектор с новой
машинной регистрацией и проверкой чтения страницы. VPN даёт сетевой путь,
но не заменяет авторизацию Confluence и не реализует персональный вход
пользователей RAG.

## Как была ограничена проверка

Отдельный образ `rag-zmostovoy-confluence-vpn:20261105` и временный контейнер
в существующей сети `rag-zmostovoy_default`, отдельное сетевое пространство,
только `NET_ADMIN` и `/dev/net/tun`, без host networking или privileged.
Hook управляет только `rag-vpn0` и маршрутом `192.0.2.104/32`; DNS и default
route не применяются. Корневая файловая система read-only, CPU/память/tmp
ограничены. Пароль передавался по stdin через SSH, Docker logging отключён.
Проверка выполнялась без PAT и без импорта документов.

Файлы образа: `apps/confluence_vpn/Dockerfile`,
`apps/confluence_vpn/route_hook.py`. Проверка маршрутизации скрипта:
`python3 -m pytest -q tests/test_confluence_vpn_route_hook.py` — 20 passed.
Образ оставлен для следующей проверки; постоянно работающий VPN-сервис
и хранение пароля не настраивались.
