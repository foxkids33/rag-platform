# Проверка переносимой установки Confluence RAG

Дата: 21 октября 2026 года. Этот документ отделяет выполненные проверки от условий, которые ещё нужно подтвердить. Реальные `.env`, существующие БД, корпоративные страницы и удалённая установка не использовались в проверках ниже.

**Результат:** чистый локальный экземпляр запущен в Docker; подтверждён полный путь выбранной синтетической страницы от Confluence API до индекса, поиска, ответа с источниками и истории, включая сохранение после пересоздания контейнеров. Подготовлен архив исходников; все четыре образа успешно собраны из его распакованного содержимого. Вместо настоящих Confluence и моделей использованы отдельные тестовые HTTP-сервисы. Это проверка работоспособности интеграции, а не оценка качества модели или допуск к промышленной эксплуатации.

Модульные тесты запускались из `/tmp`, чтобы настройки приложений с `env_file=".env"` не читали конфигурацию рабочего проекта. `RUN_DATABASE_TESTS` был исключён из окружения. Кэш pytest вынесен в `/tmp`.

```bash
# Рабочая папка: /tmp. RAG_ROOT — абсолютный путь к исходникам.
env -u RUN_DATABASE_TESTS PYTHONPATH="$RAG_ROOT/apps/api" \
  "$RAG_ROOT/apps/api/.venv/bin/python" -m pytest "$RAG_ROOT/apps/api/tests" \
  -q -o cache_dir=/tmp/rag-clean-review-api-pytest-cache
env -u RUN_DATABASE_TESTS PYTHONPATH="$RAG_ROOT/apps/worker" \
  "$RAG_ROOT/apps/worker/.venv/bin/python" -m pytest "$RAG_ROOT/apps/worker/tests" \
  -q -o cache_dir=/tmp/rag-clean-review-worker-pytest-cache
```

Пропущенные тесты API требуют явного `RUN_DATABASE_TESTS=1` и предварительно мигрированной одноразовой PostgreSQL. Они не должны запускаться против существующей базы пилота.

## Полный локальный сценарий

На новых volumes запущены шесть сервисов установки и отдельный седьмой сервис с синтетическими ответами Confluence, embedding и chat API. Исходная БД содержала **0 рабочих областей и 0 баз знаний**. Прямой режим не требовал регистрации коннектора.

Подтверждены следующие действия:

1. API сообщает режим `direct`, не раскрывает настроенные секреты. Попытка импортировать страницу `999` из `PRIVATE` с подставленным разрешённым ключом `TEAM` отклоняется по фактическому пространству страницы.
2. Выбранная страница `TEAM/101` проходит цепочку **Confluence → MinIO → долговечное задание PostgreSQL → worker → embedding → `READY`**. Используется настоящий локальный MinIO и настоящие PostgreSQL/Redis; ответы внешних систем синтетические.
3. Повторный импорт пропускает неизменённую страницу без дубликата. Гибридный поиск находит её; обычный и потоковый ответы содержат валидные ссылки на источники.
4. Исключение документа из поиска, повторное включение и удаление синтетического документа работают.

Машиночитаемый отчёт текущего локального прогона: `/tmp/rag-clean-qa-jg5vf5vl/integration-report.json`. В нём явно указаны `synthetic=true` и `model_quality_evaluation=false`. Статический ответ тестового chat API проверяет обработку контракта и SSE, а не способность модели отвечать по документации.

В браузере с настоящим локальным API проверены первый вход без автоматического POST, прямой список пространств, дерево страниц, выбор checkbox, импорт до `READY`, потоковый ответ с источниками и сохранение истории. Отдельный браузерный сценарий с мокированным API подтверждает явное создание рабочей области, отсутствие дополнительного создания после перезагрузки и пустое начальное состояние после удаления последней области. Горизонтальный выход за экран не обнаружен на ширинах **320, 390, 768 и 1365 px**.

В итоговом web-образе дополнительно подтверждены текущий ключ пространства `TEAM` без старого значения `KBR` по умолчанию, отсутствие PDF в разрешённых типах clean-загрузки и повторная загрузка сохранённого ответа из истории.

После `compose down` и последующего `up` пересозданы **все семь контейнеров** с сохранением именованных volumes. Сохранились та же рабочая область, документ со статусом `READY`, один диалог и два сообщения. Проверка касается обычной остановки и повторного запуска; она не заменяет восстановление из backup после потери диска.

Объектное хранилище собрано из официальных исходников MinIO, commit `7aac2a2c5b7c882e68c1ce017d8256be2feea27f`; SHA-256 исходного архива проверен до компиляции. Go и Alpine закреплены по digest; итоговый сервер запускается без root и достиг готовности в локальном сценарии. Эта проверка не означает поддержку архивированного upstream: ограничение и переход к поддерживаемому S3-хранилищу описаны в [инструкции](confluence-clean-deployment.md#объектное-хранилище-в-локальном-пилоте).

## Границы доступа и совместимости

Прямой серверный режим ограничивает сервисную учётную запись явным списком Confluence spaces. Существующий импорт с личными credentials пользователя — отдельный маршрут и другой источник полномочий; наличие allowlist в серверном браузере само по себе не означает ограничение всех способов импорта.

В приложении есть tenant и владение workspace, но нет переноса Confluence ACL отдельных страниц и групп. Общая база должна содержать только материал, разрешённый всем пользователям соответствующего tenant. Удаление документа не удаляет автоматически сохранённые ранее ответы и цитаты из истории.

LLM использует OpenAI-совместимый chat-completions API. Embedding использует отдельный контракт `POST /embed` с `input_type=query|passage`; произвольный `/v1/embeddings` и bearer-аутентификация embedding без адаптера не поддерживаются. Подробнее — в [обзоре повторного использования](REUSABILITY_REVIEW.md).

В [lock-файле](../apps/web/package-lock.json) `source-map-js` обновлён **1.2.1 → 1.2.2** в рамках существующего диапазона PostCSS. Новое требование Vite `rolldown~1.2.4` также потребовало обновить Rolldown с 1.2.3 до 1.2.14 и связанные нативные bindings; остальные прямые зависимости сохранены.

Версия `source-map-js` 1.2.2 исправляет отказ в обслуживании при обработке специально сформированных indexed source maps. Основания: [advisory GHSA-68fv-2mgg-jv7q](https://github.com/advisories/GHSA-68fv-2mgg-jv7q) и [релиз сопровождающего пакета](https://github.com/7rulnik/source-map-js/releases/tag/v1.2.2).

Это инструменты разработки/сборки; production frontend отдаётся nginx. Наличие advisory не означает доказанную эксплуатацию текущего развёртывания.
