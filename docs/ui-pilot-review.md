# Локальное обновление UI пилота

## Что изменено

- Создание и выбор диалога открывают вкладку «Чат», включая выбор уже активного
  диалога из раздела Confluence. Ошибка создания оставляет текущий раздел открытым.
- Документы и импортированные страницы можно искать по названию, файлу или ID,
  фильтровать по статусу. Первые 50 строк показываются сразу, остальные — по кнопке.
- В Confluence можно вставить ID или ссылку с `pageId` / `pages/ID`; неверные ID
  и неразрешённые пространства отклоняются до запроса импорта. Убран тестовый ID
  из начального значения поля, добавлены список выбранных страниц и снятие выбора.
- Пакетный импорт показывает прогресс передачи отдельно от индексации. При сбое
  пакета оставшиеся страницы остаются выбранными; успешные не отправляются повторно.
- Обновление пространств сбрасывает кэш дерева, а смена workspace — выбор страниц.
- Запоздалые ответы API не подменяют документы и сообщения после смены области
  или создания диалога. Старые запросы в управлении базами знаний отменяются.
- На узком экране доступна раскрывающаяся панель workspace/диалогов, статусы
  документов больше не скрываются. Исправлены размеры кнопок и переносы.
- Выбор файлов доступен с клавиатуры; добавлены фокус, подписи контролов,
  доступные сообщения об ошибках и поддержка reduced motion.

Палитра, карточки, типографика и общая структура интерфейса сохранены.
Backend, БД и BGE-профиль в этой UI-итерации не изменялись.

## Что пока не реализовано

С 17 сентября добавлена кнопка «Импортировать весь space»: коннектор обходит
доступные текущие страницы через пагинацию `/rest/api/content`, включая страницы
вне дерева homepage. После обхода UI запрашивает подтверждение с числом страниц
и отправляет их пакетами по 10. Обычная галочка родительской страницы по-прежнему
не включает потомков. Вложения и черновики в массовый импорт страниц не входят.

Для этого дополнения нужно обновить API (миграция `0011_connector_space_pages`)
и web, затем перезапустить коннектор на компьютере. Команды ниже относятся только
к предыдущей UI-итерации; для всего space см. [обновление импорта space](whole-space-import.md).

Пакеты импорта инициирует открытая вкладка Confluence. При уходе из раздела
или смене workspace дальнейшие пакеты не отправляются и опрос останавливается;
уже принятое сервером задание может завершиться и попасть в индексацию. Его
документы нужно проверять в исходном workspace. Для массового импорта нужна
отдельная серверная задача с возобновлением, независимая от открытой вкладки.

## Обновить только web вручную

С компьютера из корня проекта (не использовать старый архив, собранный до UI-правок):

```bash
rsync -av \
  apps/web/src/App.tsx \
  apps/web/src/ConfluenceImportPanel.tsx \
  apps/web/src/KnowledgeBaseManager.tsx \
  apps/web/src/styles.css \
  root@192.0.2.60:/root/rag-kbr-v01/apps/web/src/
```

На сервере, самостоятельно:

```bash
cd /root/rag-kbr-v01
export COMPOSE_PROJECT_NAME=rag-kbr-v01
export RAG_ENV_FILE=/root/rag-kbr-v01/.env
export RAG_SERVICE_ENV_FILE=/root/rag-kbr-v01/.env
export RAG_COMPOSE_FILE=/root/rag-kbr-v01/deploy/docker-compose.server.yml

# Запишите текущий image ID для отката до сборки нового образа.
docker inspect --format '{{.Image}}' rag-kbr-v01-web-1

bash scripts/deploy/compose-server.sh config --quiet &&
bash scripts/deploy/compose-server.sh build web &&
bash scripts/deploy/compose-server.sh up -d --no-deps --no-build web
```

После старта nginx обновить вкладку браузера. Проверить «Confluence → + Новый»,
поиск по списку страниц и открытие истории на узком экране. API, worker, БД,
MinIO, Redis и embedding пересоздавать не нужно. Порт остаётся 15173.

Для отката использовать сохранённый ID: присвоить ему тег `rag-kbr-v01-web:latest`
командой `docker image tag <IMAGE_ID> rag-kbr-v01-web:latest`, затем повторить только
`up -d --no-deps --no-build web`. Не очищать старые образы до проверки обновления.
Серверные команды автоматически не выполнялись.

Порядок локальных браузерных проверок: [UI tests](ui-navigation-checks.md).
