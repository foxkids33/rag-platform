# Авторизация, PDF и изображения — 5 ноября 2026

## Архитектура и данные

Документы и их оригиналы хранятся в серверном MinIO, фрагменты и векторы —
в PostgreSQL/pgvector, чаты и пользовательские сессии — также в PostgreSQL.
Локальный Confluence Connector нужен для чтения источника, а не для хранения
готового индекса. Сон ноутбука не удаляет загруженные документы.

На общем сервере Docker использует `/home/data/docker`. Заполнение этого
раздела относится к серверу, а не к ноутбуку. Оригиналы, индексы, модели,
образы и логи занимают отдельное место; размер корпуса нельзя приравнивать
к занятому месту всего сервера. Очистка чужих проектов не выполняется.

## Вход и изоляция

- Password mode: регистрация обычного пользователя, вход, выход.
- Единственный администратор создаётся через CLI, не через регистрацию.
- Администратор видит существующие данные своего deployment tenant.
- Новые пользователи видят только собственные пространства, чаты,
  документы и личные базы знаний. Старые KB доступны администратору.
- Общий корпоративный Confluence-коннектор доступен только администратору;
  регистрация не выдаёт доступ к корпоративным статьям.
- Cookie `__Host-rag_session`: Secure, HttpOnly, SameSite=Lax, Path=/.
  В БД находится только хэш случайного сессионного идентификатора.
- Пароли хэшируются scrypt, сессия отзывается при выходе.
- Изменения требуют Origin и X-CSRF-Token. Токены не кладутся в localStorage.
- Ошибки валидации не отражают пароли; приватные ответы имеют no-store.
- Rate limits для входа/регистрации действуют в nginx и PostgreSQL.
- Загрузки проверяются nginx auth_request до передачи multipart в API.
- OIDC mode сохранён для других конфигураций.

Это прикладные проверки и базовое усиление защиты, не результат внешнего
пентеста и не сертификация промышленной готовности.

## Форматы

| Формат | Обработка |
| --- | --- |
| TXT, MD | Текст; код в Markdown сохраняется отдельными блоками |
| CSV | Строки и столбцы, определение разделителя |
| JSON | Структурированное текстовое представление |
| HTML/HTM, XML | Текст без выполнения скриптов/внешних XML-сущностей |
| DOCX | Абзацы, заголовки и таблицы OpenXML, лимиты архива |
| PDF с текстом | CPU PDFium, без зависимости от Docling |
| PDF-скан | Рендер страниц и OCR Tesseract rus+eng |
| PNG, JPG/JPEG, WebP, TIF/TIFF | OCR и отдельное описание vision-моделью |

Описание схем и графиков выполняет существующая корпоративная модель через
внутренний endpoint. Изображения отправляются как ограниченные собственные
bytes, URL из документов не загружаются. OCR/vision маркируются как
производное распознавание и могут ошибаться. Дословность кода из OCR не
доказывает его соответствие исходным пикселям или безопасность исполнения.

Автоматическое извлечение вложенных картинок из DOCX и Confluence в этой
версии не добавлено: изображения можно прикрепить отдельными файлами.

## Лимиты по умолчанию

- Обычный пользователь: файл до 25 MiB, изображение до 10 MiB.
- Личное хранилище: 512 MiB; суммарно новые обычные аккаунты — 2 GiB.
- До 10 пространств, 100 документов в одном пространстве.
- До 10 личных KB и 10 версий каждой KB, 100 документов в версии.
- До 100 зарегистрированных обычных аккаунтов.
- Для PDF по умолчанию нет лимита числа страниц. Воркер обрабатывает PDF группами до 10 страниц с отдельным бюджетом OCR для каждой группы. Лимиты текста, вызовов vision и общего времени проверяются на весь PDF.
- Изображение до 16 мегапикселей, TIFF до 10 кадров.
- Парсер запускается отдельным процессом с ограничениями времени,
  памяти и CPU. Нечитаемые файлы не объявляются READY без извлечённого текста.

Квоты ограничивают новые пользовательские загрузки. Старые документы не
удаляются и не пересчитываются задним числом. Временные данные новых API
и worker ограничены tmpfs, новые application-логи — ротацией.

## Управление защищённым deployment

После завершения выкладки использовать на сервере:

```bash
cd /home/intern/ZMostovoy/rag-platform
sudo bash scripts/deploy/compose-secure.sh ps
sudo bash scripts/deploy/compose-secure.sh logs --tail 80 api worker web
```

HTTPS endpoint: `https://192.0.2.122:15173`.
Старый HTTP-адрес перенаправляется на HTTPS.

Сертификат стенда самоподписанный, не корпоративный CA. Отпечаток SHA-256:

```text
78:16:CA:33:D3:0C:DA:CC:94:E4:18:49:73:90:97:1A:2D:0B:5F:0B:F1:81:16:0D:B5:DB:FB:CA:CC:9F:9A:22
```

Не отключать проверку TLS глобально и не принимать неизвестные сертификаты.
Для автоматических проверок используется конкретный `tls.crt`. Для
постоянного доступа коллег нужен сертификат доверенного корпоративного CA.

Пароль администратора не публикуется в документации/логах. Локальный
приватный файл оператора: `.storage/secure-upgrade-20261105/admin-credentials.json`.

Серверный каталог `.storage/auth-images-20261105.IGr3FQ/` — не одноразовый
кэш: его `secure.env` и `tls/` используются текущим deployment. Не удалять
его при очистке диска. Образы и конфигурацию запуска сохранять до
планового переноса runtime-файлов и обновления Compose.

Резервная копия БД и исходная конфигурация находятся на сервере в собственном
каталоге `.storage/auth-images-20261105.IGr3FQ/backup/`. Если после создания
пользователей нужен откат, нельзя открывать пилот без авторизации: оставить
защищённую или maintenance-конфигурацию и восстановить совместимый код.
