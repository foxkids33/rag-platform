## Устранённые расхождения

1. SSE больше не описывается как `application/json`: указан `text/event-stream`
   и реальные события metadata/token/done/error, с оговоркой о буферизации.
2. Long-poll коннектора описывает типизированный lease 200 и пустой ответ 204.
   Runtime response validation не менялась.
3. OIDC user token и машинный credential имеют отдельные security schemes.
   В пилоте пользовательский токен не объявляется обязательным; машинная
   защита остаётся обязательной.
4. Multipart upload содержит схемы важных фактических ошибок и успешного 201.

Это сверка схемы и целевые проверки, не выполнение всех CRUD/import-операций
на сервере, не новый benchmark качества и не нагрузочная проверка.
Для остальных операций перечень инфраструктурных error statuses пока не
исчерпывающий. Общие правила — в [контракте API](api-contract.md).
