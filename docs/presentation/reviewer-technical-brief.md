# Confluence AI Reviewer: технический бриф

Подготовлено локально 9 октября 2026 года, без запуска стенда, сети или модели.
Описание опирается на frozen v8 для Confluence Data Center 9.2.4 и сохранённые
проверки. Это помощник автора troubleshooting-статей, не автоматический
технический рецензент с гарантией правильности.

## Что движется между компонентами

```text
TinyMCE → снимок черновика → Java/OSGi plugin → LLM → проверки результата → решение автора
```

JavaScript в штатном редакторе копирует DOM, добавляет идентификаторы источников
только в копию и отправляет snapshotId, заголовок, editor HTML и контекст страницы
в servlet плагина. Живой документ при запуске проверки не изменяется.
Это именно несохранённый текст автора, а не последняя опубликованная версия.

Java выделяет заголовок, текстовые фрагменты и кандидаты команд. Внешнему
корпоративному vLLM передаются **заголовок, полный HTML и JSON-фрагменты**;
не только короткие snippets. Командный проход также получает HTML для контекста.
Поэтому согласовывать нужно передачу содержимого статьи, а не только метаданных.

Первый синхронный model call оценивает десять критериев корпоративного чек-листа:
структуру, контекст, стиль, техническую точность, полноту, исполнимость и другие.
При наличии кандидатов команд следует второй, последовательный проход с отдельным
контрактом результата. Это не два независимых агента и не голосование моделей.

Десять критериев: структура, заголовок, контекст, жанр, стиль, точность технических
сведений, полнота и проверяемость, исполнимость, оформление технических данных,
практическая ценность. Условные требования применяются по контексту, а не по
фиксированным названиям разделов. REQUIRED — существенная конкретная проблема;
UNCERTAIN — недостающие сведения без готовой замены. Косметические SUGGESTION
исключены из prompt. Это политика анализа, не гарантия точности каждого finding.

## Ограничения запроса и результата

Общий node-local semaphore допускает две проверки на узел Confluence и удерживается
на оба этапа. Проверяются размер статьи, конфигурация и пустой ввод; у каждого
HTTP-запроса есть timeout. Completion ограничен 4 MiB wire bytes, включая envelope
и reasoning. Запрос с исчерпанным лимитом ответа не считается успешной проверкой
только потому, что JSON выглядит завершённым. Автоматических повторов нет.

Ошибка общего этапа завершает проверку. Ошибка командного этапа сохраняет общий
отчёт с явным предупреждением о неполноте. Строгий парсер проверяет контракт;
Java сверяет source_id и исходную цитату с конкретным фрагментом. Для команд
важны точные символы, для обычного текста допускается нормализация пробелов.
Неподтверждённая цитата теряет готовую замену; некоторые рискованные изменения
условий или операций также блокируются. Это ограниченные guards, не доказательство
безопасности команды или правильности vendor-синтаксиса.

## Применение остаётся решением человека

Ответ привязан к snapshotId. Перед Apply браузер повторно проверяет исходный текст,
DOM-положение, окружающий контекст и параметры макроса. Несовместимое изменение
делает предложение stale: прежнюю замену применять нельзя. Изменение выполняется
минимальной текстовой разницей через DOM Range внутри native undo transaction,
а не заменой всей страницы. Автор может изменить предложение, пропустить его
или сделать штатный Undo. Отмена ожидания в браузере не гарантирует прекращения
уже начавшегося серверного model call.

Проверка опубликованной страницы — отдельный сценарий: публичный PageManager
получает storage XHTML после VIEW-проверки; отчёт содержит версию страницы.
Backend не записывает страницу и не публикует изменения. Apply действительно
меняет черновик в редакторе, поэтому всё решение нельзя называть read-only.

## Доступ и выбор Java-плагина

Используются существующая Confluence session, licensed user и нативный XSRF-токен.
Для текущей страницы нужны VIEW+EDIT; для новой — VIEW пространства, CREATE
и проверка указанного родителя. Это лицензированный доступ пользователя Confluence,
не отдельная коммерческая лицензия Reviewer. Текст считается недоверенным вводом;
вывод экранируется, макросы и shell-команды не исполняются.
Нативная session/XSRF-защита не заменяет авторизацию модельного API:
HttpVllmClient v8 не добавляет service-auth header. Перед production отдельно
согласовываются классификация передаваемых данных, TLS и service authentication.

Java/P2/OSGi позволяет пользоваться нативными permission API, SAL-настройками
и жизненным циклом Confluence без отдельного прикладного microservice и собственной
копии пользователей. UI при этом написан на JavaScript; модель работает отдельно.
Компромисс — синхронное ожидание занимает servlet thread; общей очереди и
cluster-wide лимита пока нет.

## Где работает модель и где хранится состояние

Локальный demo clone — Tomcat/JVM и отдельный управляемый Synchrony JVM,
не контейнер Reviewer. Bytecode рассчитан на Java 17, проверки выполнялись на JVM 21.
Веса модели находятся на корпоративном inference-сервере, а не в Confluence.
Контейнеризация общего serving не превращает его в компонент Java-плагина.
GPU-планирование, токенизация и KV cache относятся к модельному серверу;
node-local semaphore не ограничивает все запросы общего LLM, включая RAG.

Recorder на 28001 — временный evaluation-инструмент с журналом запросов и бюджетом,
не обязательная часть production-архитектуры. Настройки модели сохраняются через
SAL; штатного постоянного архива всех review-запросов плагин не создаёт.

## Проверенное и незавершённое

Frozen v8 имеет SHA-256 `ca4a77e1cf38df3a8cb35eddb9f8c08fe7a5c3ed64dffa88cf4c27d5496e6531`.
Текущий локальный src/main совпадает с frozen snapshot; это не подтверждает живой
runtime сегодня. На freeze было 237 PASS и 2 opt-in SKIP. Позже добавлены regression
тесты открытого no-op coverage дефекта: 8 из 14 пока FAIL; исправление не выпущено.

Репетиция 8 октября подтвердила native Review, минимальный Apply и точный full-HTML
Undo на собственном fixture; published v1 не менялась. В репетиции footer Confluence
показывал `Can't save changes`: autosave/save и production readiness не объявлены
подтверждёнными. Правильность всех замечаний модели также не доказана.
Автоматической интеграции Reviewer с RAG, анализа изображений и получения vendor
manuals нет; это направления развития, а не текущие возможности.
